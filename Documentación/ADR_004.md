# ADR 004: Mecanismo de Autorización para Acceso a Correos

* **Estado:** Aceptado

## Contexto y Declaración del Problema
Para el UC1, el sistema debe sondear y escanear el correo electrónico de los usuarios. Pedir y almacenar contraseñas de usuarios es un riesgo de seguridad crítico e inaceptable (violación de QA5). ¿Cómo podemos acceder a la bandeja de entrada del usuario de forma segura y revocable?

## Drivers
* QA5: Seguridad y Privacidad (Acceso seguro y autorizado).
* UC1: Sondear y escanear correos.

## Decisión
Se implementará **OAuth 2.0** como mecanismo exclusivo para el acceso a las cuentas de correo (ej. integraciones con Google Workspace / Microsoft Graph).

El sistema solicitará al usuario permisos mediante el flujo de código de autorización (Authorization Code Flow). Se solicitará el nivel de permiso (*scope*) más restrictivo posible (ej. solo lectura). Los *Refresh Tokens* obtenidos se almacenarán cifrados en reposo en la base de datos.

## Consecuencias
* **Bien:** La contraseña del usuario nunca pasa por nuestros servidores.
* **Bien:** El usuario puede revocar el acceso a "Trotamundos" directamente desde su proveedor de correo en cualquier momento.
* **Mal:** Si el *Refresh Token* expira o es revocado, el sistema dejará de escanear viajes en silencio; será necesario notificar al usuario para que vuelva a iniciar sesión.
* **Mal:** Añade complejidad al flujo de registro (Onboarding) del usuario.
